# Sentry v1.0.2 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This patch adds the packaged
production CLI and consolidates active documentation. The unsigned archive uses
online Linux runtime bootstrap. See the [official Release page](https://github.com/Mert1026/Sentry/releases/tag/v1.0.2)
for publication status, exact source identity, ZIP/checksum and PowerShell commands
for both fresh installation and updating an existing installation.

## Included

- The registered `sentry cli` command works from any folder after setup and a new
  terminal. It uses the included Electron runtime; no Windows Node/pnpm/Git or
  source checkout is required.
- Commands use the same Desktop broker, canonical projects and QA runs as the UI.
  The CLI frontend never opens its own database or constructs agents. Environment
  settings cannot select the development/direct transport in the packaged CLI.
- Argument forwarding, Unicode and paths with spaces, complete UTF-8 JSON output,
  stderr and exit codes are preserved. Sealed archive verification requires the
  frontend and `CLI.md`; corrupt or incomplete distributions refuse execution.
- `CLI.md` includes operational examples. `INSTALL.md` covers prerequisites,
  registration, upgrades, recovery boundaries and troubleshooting. Documentation
  links inside the archive resolve locally or to the exact source commit.
- Active docs are consolidated; historical reports/screenshots remain indexed
  at immutable source tags. No release history is rewritten or old asset replaced.

## CLI examples

Open Desktop first and configure providers in Settings. For automation, always
pass `--json`, parse one stdout JSON document and inspect `ok` / `error.code`.
Human diagnostics go to stderr. Replace ID/path placeholders with real values;
these are individual examples, not one script to execute top to bottom.

```powershell
sentry open
sentry cli capabilities --json
sentry cli agent list --json
sentry cli agent doctor deepseek --json
sentry cli project add "C:\Projects\SampleApp" --json
sentry cli project list --json
sentry cli project show proj_ID --json
sentry cli project revisions proj_ID --json
sentry cli project update proj_ID "C:\Projects\SampleApp" --json
sentry cli project doctor proj_ID --json
```

Choose Full or Targeted QA. Start is async by default and returns `data.runId`
and an operation ID; keep that run ID before polling. Selected providers may
charge for requests. Do not retry an uncertain start blindly.

```powershell
sentry cli run start proj_ID --mode full --agents opencode,deepseek,glm --json
sentry cli run start proj_ID --mode targeted --agents deepseek --paths src/auth,src/api --json
sentry cli run start proj_ID --mode full --agents opencode --wait --timeout-ms 1800000 --json
sentry cli run list proj_ID --json
sentry cli run show run_ID --json
sentry cli run status run_ID --json
```

Fetch results after a terminal status, or export JSON/log files:

```powershell
$reports = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'Sentry Reports'
New-Item -ItemType Directory -Path $reports -Force | Out-Null
sentry cli run result run_ID --json
sentry cli run export run_ID --format json --out (Join-Path $reports 'result.json') --json
sentry cli run export run_ID --format log --out (Join-Path $reports 'result.log') --json
```

Cancellation and deletion are separate, explicit operations. Project deletion
removes Sentry-managed data/history while preserving the imported source folder:

```powershell
sentry cli run cancel run_ID --json
sentry cli project delete proj_ID --yes --json
```

See the [complete CLI contract](../beta/cli.md) for errors, exit codes, identity,
timeouts, response limits and the same-user trust boundary. Client identity is
informational, not authentication. Desktop must stay open; disconnecting the
CLI does not cancel a run owned by the runtime.

## Updating an existing installation

Use the new Release page's **Update an existing installation** PowerShell block.
Finish or cancel active work, stop Sentry and securely back up the actual stopped
runtime data and Desktop profile. Download/verify the exact new ZIP and sidecar,
extract to a separate version/source directory, run its setup/tools, then open a
new terminal and verify the matching runtime, version, existing history/settings
and `sentry cli capabilities --json`. Keep the previous matched archive/runtime
and stopped backup until acceptance. Do not delete WSL or user data to upgrade.

Setup registers the new per-user command. If an archive moves, run its
`sentry.ps1 register-command` from the new location. There is no automatic updater;
binary rollback alone does not authorize downgrading a migrated database. Follow
the [upgrade/recovery guide](../setup/distribution.md#explicit-release-upgrade-repair-and-source-beta-migration).

## Compatibility and verification limits

Product version1.0.2, runtime protocol1. Database schemas/migrations, provider/model/
tool pins, same-account/machine DPAPI credential boundaries and revision hash
formats stay unchanged. Existing v1.0.0/v1.0.1 ZIPs and tags retain their bytes.

The initial supported desktop remains Windows11 x64/WSL2; native Linux Desktop
is deferred. Linux Node>=22, pnpm9.12.3, systemd user services, bubblewrap and socat
remain prerequisites in WSL. Setup needs internet. No signed MSI/MSIX installer,
offline install, automatic updater or macOS support is included. A prepared-host
packaged test does not establish clean-machine provisioning. Paid campaigns and
actual elevated disk compaction are separate operator actions.
