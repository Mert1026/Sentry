# Sentry v0.1.0-beta.1

First source beta of Sentry, a local-first AI QA application. Three agents
independently investigate one immutable snapshot and return evidence/findings.
This pre-release is for early testers, not production use. Consult the
[validation report](v0.1.0-beta.1-validation.md) before distribution.

## Supported systems

- Windows 11 with WSL2 (Ubuntu preferred for runtime).
- Native CachyOS with graphical session and systemd user services.

Other native Linux distributions/macOS are unsupported. On 2026-10-09 the owner
confirmed 3/3 success on both hosts and authorized release preparation. This is
owner-reported acceptance, not an independent rerun by the agent. Manual
active-provider cancellation/exit/update and CachyOS maintenance were not
independently verified; automated safety regressions and Windows idle quit pass.

## Features

- Desktop project/run workspace, immutable revisions, evidence inspection,
  token usage, JSON/log export and native Save As.
- Full/Targeted QA: OpenCode 1.18.32, DeepSeek SDK 0.1.5-rc.2, and GLM
  through Claude Code 2.1.270; cancellation and persistent history.
- Host-specific setup/diagnostics, isolated Linux execution, runtime handshake
  and CLI control of the running Desktop.
- Provider/model settings and encrypted persistence when OS storage is available.
- Safer maintenance shutdown, awaited Electron cleanup, Linux startup failure
  feedback, and private-file exclusions during staging.

## Installation

Git, Node >= 22, pnpm 9.12.3, internet, repository access and API accounts/credit
are required. Once the tag is available:

```text
git clone --branch v0.1.0-beta.1 https://github.com/Mert1026/Sentry.git
cd Sentry
```

Windows: `.\sentry.ps1 setup`, then `sentry open`.
CachyOS: `./sentry setup`, then `./sentry open` in a graphical session.
Configure Settings → Providers, check Environment, add a project and start QA.
See [getting started](../beta/getting-started.md) and
[CachyOS setup](../setup/cachyos-launcher.md).
Cancel active work and wait before stop/maintenance. Verify Environment and
`sentry cli capabilities --json`; process survival does not prove readiness.

## Updates

Beta tags keep the validated revision pinned. `sentry update` follows development
origin/main and refuses detached tags. Opting into main can install untested
changes. Later betas need explicit tag checkout/setup; see [updating](../beta/updating.md).

## Known limitations

- Source installation only; no signed installer, AppImage or tested binary asset.
- Setup can require Windows reboot or CachyOS package installation.
- API credit/provider availability and valid endpoints/models are necessary.
- Sandbox trust tests are unverified where user-unit mounts are unavailable.
  Ubuntu CI does not prove native CachyOS acceptance.
- Legacy merger/verifier/issue-ingestion components remain for compatibility;
  merge/verification ingestion is not exposed through current Desktop RPC.
- Active work is not promised to continue after exit. Cancel and wait first;
  interrupted work uses existing recovery. Candidate active-run exit acceptance
  must be recorded separately.
- Private repository: testers need access to code/releases.

## Security and privacy

Providers receive relevant prompts/source/evidence; review privacy/pricing before
using confidential code. Sandbox/evidence controls remain. safeStorage uses
Windows DPAPI or the available Linux backend; assess that backend on target.
Unavailable encryption has no plaintext persistence fallback. Review logs and
exports; never share keys, credential stores, databases or retained workspaces.
