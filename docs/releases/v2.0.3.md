# Sentry v2.0.3 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This update from v2.0.2 gives the CLI full access to the app: it can
read and change everything Desktop can, including provider settings and keys (write-only). The unsigned archive
uses online Linux runtime bootstrap. See the
[official Release page](https://github.com/Mert1026/Sentry/releases/tag/v2.0.3) for exact source identity,
ZIP/checksum and PowerShell commands for both fresh installation and updating an existing installation.

## Included

- **The CLI has full access to the app.** New commands mirror the Desktop screens:
  - `provider status | set | clear | forget-all | forget-file | persist | detect-binaries` for provider modes,
    models, endpoints and keys;
  - `account status | login | logout | cancel <openai|claude>` and `account code claude <code>` for the ChatGPT
    and Claude sign-ins;
  - `runtime status | distros | select <distro> | reclaim-space`;
  - `system info | runs | environment | broker`;
  - `app language <en|bg>`;
  - `toolchain custom install <name> --command "<command>"`.
- **Keys are write-only.** A key is set from standard input (`--stdin`) or a named environment variable
  (`--env`), never from a command argument, so it does not stay in shell history or process lists. No command
  returns a stored key; `provider status` only says whether one is set.
- **The broker's allowlist is opened to match.** Only native dialogs (Save As, folder pickers) and switching
  the broker itself off stay in Desktop. `sentry cli capabilities --json` reports `fullAccess`. See the
  [CLI reference](../beta/cli.md#full-access-providers-keys-accounts-runtime-and-system).
- **CI:** the GLM and Claude release-prompt tests no longer collide when both suites run at once. No product code
  changed for this.

## Trust: read this before you script

The CLI broker has no password: any process running as your Windows user can connect to it. With full access,
such a process can set, replace or clear your provider keys, install custom add-ons and start runs. The **Local
CLI Broker** switch in Settings → Application is the control: leave it off when you are not scripting. There is
no extra confirmation, so `provider forget-all` runs as typed.

## Updating from v2.0.2

There is no database migration in this update. Your projects, runs, history, exports and provider settings are
kept.

1. **Finish or cancel active runs** and wait until they settle.
2. **Download the release ZIP and its `.sha256` file** into one folder, then run
   `sentry update <path-to-the-zip>`. It checks the checksum and, when the GitHub CLI (`gh`) is installed, the
   build attestation. It extracts beside the current install, refuses the same or an older version, backs up
   the Desktop profile and the Linux data into `Documents\Sentry backups`, then runs the new archive's own
   setup. If setup fails, the previous install is untouched.
   Alternatively run the Release page's **Update an existing installation** block.
3. **Check the result** in a new PowerShell window:

   ```powershell
   sentry version
   sentry status
   sentry cli capabilities --json
   ```

   The version must be **2.0.3**, the commit must match the Release page, and `capabilities` must list
   `fullAccess`. With the CLI broker on, try `sentry cli provider status`.

Going back to 2.0.2 is safe: no stored format changed. Restore the backup only if you want the data exactly as it
was before the update.

Updating from **2.0.1** or earlier: follow the [v2.0.2 notes](v2.0.2.md) first, or run this update with the Release
page's install block (it sets up the same runtime). Updating from **1.x**: follow the [v2.0.0 notes](v2.0.0.md);
that update has a one-way database migration.

## Compatibility and verification limits

Product version 2.0.3, runtime protocol 1. There is no database migration. Schemas change only by optional
additions: the new CLI results and the `fullAccess` capability flag. Provider and model pins, credential
encryption and revision hash formats are unchanged. Existing v2.0.2 and earlier ZIPs and tags keep their bytes.

The new CLI commands are covered by unit and integration tests against the broker; they have not been run with
paid agents. The Claude agent's account sign-in depends on the util-linux `script` tool (setup warns if it is
missing; the API key sign-in does not need it). Native Linux Desktop is deferred. Setup needs internet. There is no
signed installer, offline install, automatic updater or macOS support. Paid QA runs are separate operator
actions. See the Release page for what was verified on the packaged archive.
