# Sentry v2.0.1 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This update from v2.0.0 adds a choice of run depth
(Fast or Full), a default run time limit, reasoning effort for every agent and new CLI settings
commands, and fixes three bugs found by a QA run. The unsigned archive uses online Linux runtime
bootstrap. See the [official Release page](https://github.com/Mert1026/Sentry/releases/tag/v2.0.1)
for exact source identity, ZIP/checksum and PowerShell commands for both fresh installation and
updating an existing installation.

## Included

- **Run depth:** Fast plans at most 3 checks, Full (the default) as many as the time window allows,
  up to 8. Both use the same window and the same extra passes (second pass, deepening, hazard
  sweep). Choose it on the project page or with `run start --depth fast|full`. The depth is shown
  on the run and in Findings by revision.
- **Run time limit:** Settings → Runtime sets the window every run gets: 3 hours (default), 6 hours,
  No limit (7 days) or a custom value from 10 minutes. The window is a ceiling, not a target, and it
  decides which extra passes still have time. The longest window a run can be given is now 7 days
  (it was 12 hours), and the CLI help and docs no longer say the default is 30 minutes (it is 3
  hours).
- **Reasoning effort per agent** in Settings → Providers, with the levels each agent's tool takes. It
  is shown on the Environment page and on the project page's agent cards.
- **CLI:** `settings show`, `settings effort <agent> <level|default>` and `settings run-limit
<default|3h|6h|none|90m|12h>` read and change those two settings; `run list` and `run status`
  report each run's `depth` and `timeLimitMs`; `capabilities` reports `settings` and `runDepth`. The
  help lists every command. See the [CLI reference](../beta/cli.md).
- **Fixes:** a symlink whose target contains a backslash is copied exactly on Linux and macOS; a
  finding title can no longer forge a status line in the human-readable log; a stored artifact whose
  path names the data root is refused before its database row is deleted.
- **Interface:** the ChatGPT sign-in choice is a two-button control; more Bulgarian translations
  (statuses, generated text, graph labels); the Details page no longer shows elapsed time; a stage
  where an agent hit a warning blinks as calm yellow stripes.

## Updating from v2.0.0

There is no automatic updater and no database migration in this update. Your projects, runs,
history, exports and provider settings are kept.

1. **Finish or cancel active runs** and wait until they settle.
2. **Stop Sentry** and **back up your data** with the backup block on the Release page. It is the
   same block as for any update: it saves the Linux data folder and the Desktop profile to a
   timestamped folder in Documents. Keep it until you have checked your history.
3. **Run the Release page's “Update an existing installation” PowerShell block** (it uses the same
   complete install block as a fresh install). It downloads the exact ZIP and checksum, verifies
   the ZIP hash, manifest hash, source identity and every file before running anything, extracts
   into a separate version directory, sets up the matching runtime, installs the pinned tools,
   registers the new `sentry` command and opens Desktop. Do not extract over the old version.
4. **Check the result** in a new PowerShell window:

   ```powershell
   sentry version
   sentry status
   sentry cli capabilities --json
   ```

   The version must be **2.0.1**, the commit must match the Release page, and `capabilities` must
   list `runDepth` and `settings`. Open Desktop: Settings → Runtime has a **Run time limit**, each
   agent card in Settings → Providers has a **Reasoning effort**, and the project page has a **Run
   depth** choice. Check that your projects and runs are listed.

Keep the previous archive and the stopped backup until you are satisfied. **Going back to 2.0.0 is
only safe from the backup.** A run started with Fast depth under 2.0.1 stores a field that 2.0.0 does
not know, and 2.0.0 reads run records strictly, so 2.0.0 may fail to list such runs. To go back,
stop Sentry, restore the stopped backup taken before the update, then run the v2.0.0 install block.
Do not run 2.0.0 over data that 2.0.1 has written.

Updating from **1.x** instead: follow the [v2.0.0 notes](v2.0.0.md). That update has a one-way
database migration (it drops issue, retest and merge history), so the backup is your only way back.

## Compatibility and verification limits

Product version 2.0.1, runtime protocol 1. Database schemas and migrations, provider and model
pins, credential encryption and revision hash formats are unchanged, except one case: a project whose
symlinks have a literal backslash in the target gets a different revision hash on its next import,
because the copy is now faithful on Linux and macOS. Existing v2.0.0 and earlier ZIPs and tags keep
their bytes.

Only the Python and .NET toolchain installers have been run end to end; the other packs are covered
by unit tests. GLM and DeepSeek reasoning effort has not been exercised against the live providers: if
a run fails after setting one, set that agent back to Default. The new `settings` CLI commands and
`--depth` are covered by tests; see the Release page for what was verified on the packaged archive.
Native Linux Desktop is deferred. Setup needs internet. There is no signed installer, offline
install, automatic updater or macOS support. Paid QA runs are separate operator actions.
