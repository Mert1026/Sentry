**Draft for owner review. No official RC is published.** The initial supported
release platform is **Windows 11 x64 with WSL2**, with Ubuntu preferred inside
WSL2. Native Linux Desktop, initially CachyOS x64, is
**DEFERRED — FUTURE NATIVE LINUX RELEASE**. Its implementation, owner-reported
functionality and unresolved acceptance evidence remain in the repository.

Current release preparation is the
[Phase 6.3 freeze handoff](v1-phase-6-3-windows-rc-freeze.md), selected merged-dev
source `c6d4769bf3179d49bb3718074d6c083f52332626`. Its private unsigned Windows
archive and verification receipts are tied to that complete SHA. Subsequent owner

GitHub Release, public asset upload or promotion to main.

Windows Electron Desktop continues to communicate with the Linux execution
runtime through WSL2. Linux Node/pnpm, systemd user services, bubblewrap isolation,
protocol verification and agent security controls remain required.

## Functionality

- Independent OpenCode, DeepSeek and GLM execution; select one, two or three agents.
- Full and Targeted QA against immutable managed project snapshots.
- Per-agent progress, findings and evidence with retained attribution.
- Persistent projects, revisions and run history; JSON/log exports.
- OS-backed secure provider storage using Windows DPAPI, with no plaintext fallback.
- Graceful cancellation, maintenance, shutdown and restart recovery.
- DeepSeek persistent Bash evidence correction without relaxing grounded findings.
- Confirmed project removal, including managed files and associated history;
  original source directories remain intact. Cancel preserves the project and
  active operations prevent removal. Missing managed folders can still be removed
  from the canonical project list.
- Explicit Windows WSL disk reclamation after confirmation and administrator
  consent. Other running distributions and active QA prevent maintenance; lock
  release is bounded and Sentry reconnects after completion or refusal. Reclaimed
  bytes depend on the disk's contents and allocation; no fixed result is promised.

Historical issue/retest compatibility remains. Merger/Verifier ingestion is not
an active stage in the current Desktop pipeline. Provider/model/SDK pins,
database schema, product version **1.0.0-rc.1** and runtime protocol **1** are unchanged.

The owner reported normal functionality on Windows and native CachyOS on
October 13, 2026, including independent agents, selection and Full/Targeted QA.
That [historical report](v1-owner-functional-acceptance-2026-10-13.md) does not
establish exact-source acceptance of a later archive.

## Install or update the unsigned Windows ZIP

Obtain the owner-approved `sentry-1.0.0-rc.1-<sha12>-windows-x64.zip`, its trusted
SHA256 sidecar and release documentation. Verify SHA256, extract into a new
version/source directory and run that archive's `.\sentry.ps1 version` to validate
the complete inventory. Follow the [distribution guide](../setup/distribution.md):

```powershell
.\sentry.ps1 setup -Distro Ubuntu
.\sentry.ps1 tools -Distro Ubuntu
.\sentry.ps1 open
```

The packaged Desktop includes Electron 36.2.1. Windows Node/pnpm/Git are not
required for packaged installation. PowerShell and usable WSL2 are required;
initial WSL installation, reboot and Ubuntu account creation may need owner actions.
Inside WSL2, standalone Linux Node >=22 (Node 22 is the CI baseline), pinned
pnpm 9.12.3, systemd user services, bubblewrap and socat must be available.
Keep sandbox controls enabled. Setup installs/builds the Linux runtime using
frozen dependencies and requires internet; it does not run paid QA.

Provider tooling, accounts, credentials and API credit are separate requirements.
Credential presence does not establish provider credit or readiness. Configure
providers in Settings and inspect Environment before starting QA. Runs may incur charges.

For updates, stop active work and Desktop/runtime gracefully, verify a new approved
archive, extract beside the existing one and run its setup. Preserve matching
stopped data/profile backups and previous runtime/archive generations. There is
no automatic update channel. This is an unsigned online-bootstrap ZIP, not an
MSI, MSIX, signed EXE or offline installer.

## Recovery and known limitations

- Native Linux Desktop release acceptance, exact-CachyOS smoke and native G10-R
  are deferred. The [large-import investigation](native-linux-large-import.md)
  remains unresolved; a comparable shared failure demonstrated on Windows would
  still block Windows publication.
- Original-beta executable credential rollback remains historical **G10 FAIL**.
  The immutable published beta is not an accepted credential downgrade target.
- **Recovery Option A was owner-approved on October 14, 2026**, only for the
  tested Windows/I1 route. Use the exact corrected I1 Desktop/runtime source
  `c78faa74717b0f430a859730e98c3c4915e7b03f` with a verified matching stopped
  historical backup. This RC does not replace that recovery target. See the
  [decision and boundaries](v1-recovery-policy-decision.md).
- Recovery requires compatible schema, matching backup generations, full
  verification before replacement, retained originals and the same compatible
  Windows account/machine/DPAPI context. No automatic schema downgrade or
  cross-account/machine encrypted-key portability is promised. Replacement
  across filesystems is not atomic; inspect interrupted swaps while stopped.
- Clean Windows provisioning, backend-unavailable sessions and every historical
  paid/failure combination are not comprehensively recorded. Previous owner
  acceptance remains distinct from exact-archive verification; no blanket paid replay is required.
