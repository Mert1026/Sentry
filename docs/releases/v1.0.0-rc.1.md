## Install or update a review candidate

Obtain the exact approved private archive and trusted SHA256 sidecar. Verify
checksum and extracted manifest, keep each version/source directory separate,
then follow the [distribution guide](../setup/distribution.md) using that archive's
own launcher. No public RC download, release tag or signing is supplied here.

Windows requires Windows11 x64, PowerShell and a usable WSL2 distro (Ubuntu
preferred). The Linux side requires standalone Node>=22, pnpm9.12.3, systemd user
services, bubblewrap and socat. The packaged Desktop bundles Electron36.2.1;
Windows Node/pnpm/Git are not required for packaged installation. Initial WSL
feature installation/account creation/reboot may need deliberate owner actions.

Native CachyOS requires x86_64, an actual graphical non-root session, systemd
user bus, supported unlocked OS keychain, bubblewrap/socat, Node>=22/pnpm9.12.3
and the platform libraries/prerequisites in the distribution guide. Keep Electron
and worker sandboxes enabled. Other native Linux distributions and macOS are
unsupported. Ubuntu build/test results are not native CachyOS acceptance.

Setup installs/builds the Linux runtime from frozen source dependencies and
requires internet. Provider tooling/accounts/credit are separate prerequisites;
configured credentials do not prove billing capability. QA can incur provider
charges. Usage evidence is limited to what the app/providers actually report.

Update by verifying a new approved archive, stopping active work and Desktop/
runtime gracefully, then running the new archive's setup. Pinned archives refuse
development `update`; there is no automatic update channel. Keep stopped data/
profile backups, previous runtime and original archives. Never delete data roots
or force-stop unrelated processes to repair installation.

## Recovery and known limitations

- **Original-beta executable rollback is unreliable for credentials.** Its
  startup can load secure storage before Electron readiness. Historical G10
  remains P1 FAIL; it is not waived or changed to PASS by these notes.
- **Recovery Option A is owner-adopted for the tested Windows/I1 scope.** The validated Windows G10-R
  route restores matching verified stopped historical data/profile using the
  exact corrected I1 Desktop/runtime pair. The owner explicitly selected A on
  October 14, 2026; the [decision record](v1-recovery-policy-decision.md) preserves
  the exact target and boundaries. This RC is not substituted as that recovery target.
- That tested route requires compatible schema and the same Windows account/
  machine/DPAPI context. No plaintext key fallback, automatic schema downgrade,
  or cross-account/computer/keychain credential portability is promised.
- Data/profile replacement across filesystems is not atomic. Preserve matching
  generations and inspect interrupted swaps while all components remain stopped.
  Native normal functionality is owner-reported working; full native G10-R
  execution has not been established by that statement.
- Archives are unsigned online-bootstrap review packages. There is no signed
  installer, offline installer or silently enabled release channel. New RC
  artifacts have distinct identities; prior physical I1 passes do not become
  exact-RC binary passes automatically.
- Clean Windows provisioning, actual backend-unavailable sessions and every
  historical failure/paid combination are not comprehensively recorded. These
  evidence limits are disclosed for owner scope decisions, not declared new
  product defects or reasons to repeat successful paid work without a material risk.

Exact-RC native CachyOS smoke remains **PENDING**, per the owner's Phase 6.1
instruction. Earlier owner-reported native functionality is retained separately;
Ubuntu packaging and WSL verification do not establish an exact native binary pass.
