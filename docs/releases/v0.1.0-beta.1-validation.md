## Findings and changes

- Electron's original asynchronous `before-quit` handler was not awaited.
  Window close/quit now waits for bootstrap and runtime cleanup, with reentry
  protection and actionable refusal. The CLI broker stays usable if QA is busy.
- Runtime run/retest promises outlive their start RPC. Shutdown now refuses
  pending work, rejects new requests after acceptance, and distinguishes
  transient in-flight requests. The client retries that transient case within
  its existing shutdown budget and preserves a runtime that refuses busy stop.
  Broken/unresponsive owned transport cleanup retains its prior bounded kill
  fallback; this is not a guarantee against power loss or runtime failure.
- Windows and Linux setup/update previously ignored failed graceful stop.
  Both now abort before source/dependency/runtime replacement. No maintenance
  force-kill shortcut was added.
- Linux `open` detects immediate process exit, logs its status and points to
  doctor. Surviving the two-second check only proves process startup.
- Runtime source staging excludes environment files, package-manager private
  configuration, credentials, databases, logs and retained workspaces.
- Verifier containment uses the OS path separator and still rejects traversal
  and symlink/junction escapes. Fixture paths now match their host platform.
- Claude argv recording uses a real cwd and preserves argument boundaries.
  Concurrent scripted suites own separate temporary HOME parents. Native-kernel
  fixtures simulate the kernel as well as absent WSL environment markers.
  OpenCode network tests use their actual fixture workspace, with isolation
  assertions unchanged. No production harness/prompt/report pipeline changed.
- Historical named quarantines are removed: verifier and Claude fixtures are
  required. Real sandbox capability remains an explicit CI prerequisite.
- Root/Desktop/runtime already used `0.1.0-beta.1`; CLI package and `qa --version`
  now match. Internal private packages retain `0.1.0` contract versions; no npm
  packages are published.
- README, beta setup/update/CLI guides, changelog, release notes and bug report
  fields cover Windows + WSL2 and native CachyOS. Beta installs stay on tags;
  `sentry update` explicitly opts into development origin/main. Branch policy,
  PR template and release/hotfix push CI establish reviewable integration.

## Tag and draft pre-release commands

Run only after owner review, final CI and required target acceptance. Use a clean
checkout of the reviewed release branch, and substitute its approved full SHA.
Do not publish or overwrite a tag if any blocker remains.

```bash
git fetch origin
git switch codex/release-v0.1.0-beta.1
git status --porcelain
gh pr checks --required
git rev-parse HEAD
git ls-remote --tags origin refs/tags/v0.1.0-beta.1
git tag -a v0.1.0-beta.1 APPROVED_FULL_SHA -m "Sentry v0.1.0-beta.1"
git push origin refs/tags/v0.1.0-beta.1
gh release create v0.1.0-beta.1 --verify-tag --draft --prerelease --title "Sentry v0.1.0-beta.1" --notes-file docs/releases/v0.1.0-beta.1.md
```

Stop if the local/remote tag already exists: inspect it and use a new version
for different source. `git status --porcelain` must be empty. With unavailable
server protection, check all three CI jobs directly if `--required` lists none.
The draft must remain unpublished until the owner approves distribution.
No assets are attached. Authorized testers install through the tagged Git clone
and host-specific setup instructions in [README](../../README.md); private
repository access is required.
