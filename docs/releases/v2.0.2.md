# Sentry v2.0.2 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This update from v2.0.1 adds a fifth agent (Claude), notes
for the agents, a secrets check, a real headless browser for web checks, a model picker with an updatable
model list, a command to install an update from a ZIP you downloaded, a redesigned Providers page, and many
fixes found by QA runs on Sentry's own code. The unsigned archive uses online Linux runtime bootstrap. See the
[official Release page](https://github.com/Mert1026/Sentry/releases/tag/v2.0.2) for exact source identity,
ZIP/checksum and PowerShell commands for both fresh installation and updating an existing installation.

## Included

- **A Claude agent**, the fifth and opt-in like ChatGPT. It runs Anthropic's own Claude Code app against
  Anthropic, apart from the GLM agent (GLM keeps its Z.AI endpoint and token; the Claude agent never receives
  them). Sign in with an Anthropic API key or with a Claude account (**Sign in with Claude**: open the link,
  paste the code back). It has its own model and reasoning effort. In the CLI it is `claude`.
- **Notes for the agents.** Before a run, write what to focus on, known problems and things to leave alone:
  one note for everyone, or one per agent. Notes are saved with the run, shown on the run page and included in
  findings exports. They cannot switch off the safety rules, the network limits or the secrets check.
  **Settings → Application → Note length limit** sets how long a note may be: 5,000 characters (default),
  20,000, No limit or a custom length.
- **Secrets check.** Every run makes each agent also search for hard-coded secrets. Each agent's box shows a
  red, green or amber light, and known secret formats are removed from agent messages, findings and evidence
  before they are stored. A run option (`run start --no-secrets`) turns it off for the shortest run.
- **A headless browser for agents.** Setup installs one managed browser (about 350 MB, once), so checks on web
  pages no longer end inconclusive for lack of one.
- **Run depth:** a Fast run now plans at most 2 checks (was 3) and skips the deepening round and the hazard
  sweep, so it is much shorter. Full is unchanged. **Settings → Application → Run time limit** moved here from
  Settings → Runtime.
- **A model picker** for every agent: a searchable list with each model's exact id, context size and release
  date, an **Update list** button that fetches the public model catalog (models.dev), and your own model id as
  the last row. Agent cards on the project page now show the model you chose (DeepSeek, GLM and Claude kept
  showing a placeholder).
- **`sentry update <archive.zip>`** for the packaged Windows release (see below). The distribution workflow
  attests the ZIPs it builds.
- **Findings:** export from Findings by revision saves one .md, .json or .txt file; a failed report no longer
  loses a finished investigation; token counts mean the same for every agent.
- **CLI:** `settings note-limit`, `models list` and `models update`, plus `project suggest-targets`,
  `toolchain` and custom add-on commands. **Settings → Application** has a button that saves the whole CLI
  command reference as a Markdown file. See the [CLI reference](../beta/cli.md).
- **Interface:** the Providers page has one wide card per agent with its logo, a Ready / Needs a key chip and
  custom drop-downs; the sidebar opens and closes from a tab on its edge; the run page has stage bars that read
  as one line, a structured header, local-time dates, plain-language agent errors you can close, and never
  scrolls the page. More Bulgarian translations.
- **Fixes** from QA runs on Sentry's own code: Markdown export escapes brackets and angle brackets, stored
  events have secrets removed, project paths that escape the data folder are refused, the hazard sweep no
  longer scans what an agent unpacked into its workspace, agents no longer reinstall dependencies Sentry
  already installed, the interface router is updated to a version without a known open-redirect advisory,
  a silent agent no longer holds a finished run for long, and setup and `sentry doctor` now
  detect a system where the GLM sandbox starts but refuses nested user namespaces. The changelog has the full
  list.

## Updating from v2.0.1

There is no automatic updater and no database migration in this update. Your projects, runs, history, exports
and provider settings are kept.

1. **Finish or cancel active runs** and wait until they settle.
2. **Stop Sentry** and **back up your data** with the backup block on the Release page. It saves the Linux data
   folder and the Desktop profile to a timestamped folder in Documents. Keep it until you have checked your
   history.
3. **Run the Release page's “Update an existing installation” PowerShell block.** It downloads the exact ZIP and
   checksum, verifies the ZIP hash, manifest hash, source identity and every file before running anything,
   extracts into a separate version directory, sets up the matching runtime and the pinned tools, installs the
   headless browser, registers the new `sentry` command and opens Desktop. Do not extract over the old version.
   (v2.0.1's own `sentry update` only refuses; the new command exists from v2.0.2 on.)
4. **Check the result** in a new PowerShell window:

   ```powershell
   sentry version
   sentry status
   sentry cli capabilities --json
   ```

   The version must be **2.0.2**, the commit must match the Release page, and `capabilities` must list `models`.
   Open Desktop: Settings → Application has a **Run time limit**, a **Note length limit** and a **CLI command
   reference** download; Settings → Providers shows the Claude card. Check that your projects and runs are
   listed.

### From v2.0.2 on: `sentry update <archive.zip>`

Download the release ZIP and its `.sha256` file into one folder, then run
`sentry update <path-to-the-zip>`. It checks the checksum and, when the GitHub CLI (`gh`) is installed, the build
attestation (pass `-SkipAttestation` for a ZIP built before attestations existed). It extracts beside the current
install, refuses the same or an older version, backs up the Desktop profile and the Linux data into
`Documents\Sentry backups`, then runs the new archive's own setup. If setup fails, the previous install is
untouched. It never downloads anything by itself.

Keep the previous archive and the stopped backup until you are satisfied. **Going back to 2.0.1 is only safe from
the backup.** A run started under 2.0.2 can store fields 2.0.1 does not know (notes, the secrets-check setting,
the Claude agent), and 2.0.1 reads run records strictly, so it may fail to list such runs. To go back, stop
Sentry, restore the stopped backup taken before the update, then run the v2.0.1 install block. Do not run 2.0.1
over data that 2.0.2 has written.

Updating from **2.0.0** instead: follow the [v2.0.1 notes](v2.0.1.md) first, or run this update directly (the
2.0.2 install block sets up the same runtime). Updating from **1.x**: follow the [v2.0.0 notes](v2.0.0.md); that
update has a one-way database migration.

## Compatibility and verification limits

Product version 2.0.2, runtime protocol 1. There is no database migration. Schemas change only by optional
additions: a run's `userNotes` and `secretsCheck`, the `claude` agent stack, new CLI results (`noteLimit`,
`models list`, `models update`) and the `models` capability flag. Provider and model pins, credential
encryption and revision hash formats are unchanged. Existing v2.0.1 and earlier ZIPs and tags keep their bytes.

Only the Python and .NET toolchain installers have been run end to end; the other packs are covered by unit
tests. The Claude agent's account sign-in depends on the util-linux `script` tool (setup warns if it is
missing; the API key sign-in does not need it). The model list comes from a public catalog and can lag a new
model: write the id as a custom model id. Native Linux Desktop is deferred. Setup needs internet. There is no
signed installer, offline install, automatic updater or macOS support. Paid QA runs are separate operator
actions. See the Release page for what was verified on the packaged archive.
