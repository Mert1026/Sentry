# Sentry v2.0.4 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This update from v2.0.3 makes the agents plan and investigate more
sharply (risk-ordered, narrow checks, critical-flow exploration, traced root causes), adds a per-agent switch that
ends the extra rounds once they stop finding anything, and reworks the dashboard and the run screens. The unsigned
archive uses online Linux runtime bootstrap. See the
[official Release page](https://github.com/Mert1026/Sentry/releases/tag/v2.0.4) for exact source identity,
ZIP/checksum and PowerShell commands for both fresh installation and updating an existing installation.

## Included

### Investigation quality

- **Plans read the source and rank by risk.** The planner reads the target's source before planning. Checks,
  critical flows and weak points are each ordered from most to least risky, every check and flow stays narrow
  (one module, at most three operations), and every critical flow gets a check that runs it through its public
  entry point with boundary inputs. A code comment saying a case is handled is treated as a claim to test.
- **Critical flows are explored end to end.** After the planned checks, up to five critical flows (riskiest
  first) get a turn of their own, before the deepening.
- **Root causes reach the report.** Every turn that reproduces a defect writes a `Root cause:` line (kept when the
  check is deepened), and the report copies it into the finding.
- **Severity is calibrated for libraries and injection.** A silently wrong result from a library's documented API
  is at least medium (high for ordinary input); an injection of a value only the project itself supplies is low.
- **Fewer wasted turns.** Leads are about the product only ("none other" and setup problems are not leads); a
  proven fixture error means fix the probe and rerun it; a plan written after long progress notes, or with list
  entries as objects, is still accepted.
- **Timeline messages** say the time left as "about 3 hours" or "no practical time limit" instead of thousands
  of minutes.

### New: stop extra rounds when idle

- **Settings → Providers → each agent → Stop extra rounds when idle** (off by default). When on, that agent's
  extra rounds (leads, flows, deepening, hazard sweep) end after two turns in a row reproduce no new defect, and
  the report starts. The planned checks and the second pass on undecided checks always run. It saves time and
  provider usage on runs where the planned checks already found what there is.

### Claude and GLM agents

- **Installs no longer fail in the Claude Code sandbox.** Claude Code write-protects the project's
  `node_modules/.bin`, `package.json` and lockfiles, so `npm ci` in the project folder always failed. The agents
  are now told to install into `.qa-tmp/deps` instead.
- **Long Claude runs hold up better:** a higher per-reply output cap, a `.git` placeholder race between
  overlapping commands no longer ends an investigation, a slow report is kept alive, and a report retry gets the
  full report contract again.

### Desktop

- **Dashboard** with workspace statistics: projects, QA runs, success rate, findings, typical run time, active QA
  and the runtime; runs per day over 14 days; findings by severity and by agent; active QA, recent runs and
  recent projects.
- **Run screen:** the stage list follows the real order and only shows a warning raised during the current step;
  the current operation shows what the agent is doing; the agent node's live line wraps, translates, and has
  **Show more** for long text.
- **Start QA dialog** redesigned and centred on the screen; **Cancel run** shows "Stopping run…" until the run
  has stopped.
- **Bulgarian** for the agents' steps, the run and note limits, and labels that were left in English.

The repository also gains the bug-finding benchmark harness (`benchmarks/bug-finding`), a development tool that
is not part of the installed app.

## Updating from v2.0.3

There is no database migration in this update. Your projects, runs, history, exports and provider settings are
kept.

1. **Finish or cancel active runs** and wait until they settle.
2. **Download the release ZIP and its `.sha256` file** from the Release page into one folder (for example
   `Downloads\Sentry-v2.0.4`), then run `sentry update` with the ZIP's path:

   ```powershell
   sentry update "C:\Users\you\Downloads\Sentry-v2.0.4\sentry-2.0.4-<id>-windows-x64.zip"
   ```

   It checks the checksum and, when the GitHub CLI (`gh`) is installed, the build attestation. It extracts beside
   the current install, refuses the same or an older version, asks before continuing (`-NonInteractive` skips the
   question), backs up the Desktop profile and the Linux data into `Documents\Sentry backups`, then runs the new
   archive's own setup. If setup fails, the previous install is untouched. It never downloads anything by itself.
   Alternatively run the Release page's **Update an existing installation** block, which works from any earlier
   version.

3. **Check the result** in a new PowerShell window:

   ```powershell
   sentry version
   sentry status
   ```

   The version must be **2.0.4** and the commit must match the Release page.

Going back to 2.0.3 is safe: no stored format changed. 2.0.3 ignores the new per-agent "Stop extra rounds when
idle" settings. Restore the backup only if you want the data exactly as it was before the update.

Updating from **2.0.2** or earlier: follow the [v2.0.3 notes](v2.0.3.md) and the notes before it, or run this
update with the Release page's install block. Updating from **1.x**: follow the [v2.0.0 notes](v2.0.0.md); that
update has a one-way database migration.

## Compatibility and verification limits

Product version 2.0.4, runtime protocol 1. There is no database migration. Schemas change only by optional
additions: `runtime.configure` takes an optional per-agent `stopIdle`, and the provider store keeps five new
optional settings (`SENTRY_<AGENT>_STOP_IDLE`). Provider and model pins, credential encryption and revision hash
formats are unchanged. Existing v2.0.3 and earlier ZIPs and tags keep their bytes.

The investigation changes were measured on benchmark runs with the OpenCode and Claude agents; they are prompt and
orchestration changes, so results still vary between models and runs. The Claude agent's account sign-in depends
on the util-linux `script` tool. Native Linux Desktop is deferred. Setup needs internet. There is no signed
installer, offline install, automatic updater or macOS support. Paid QA runs are separate operator actions. See
the Release page for what was verified on the packaged archive.
