# Sentry v1.0.0 Stable — Windows

Release notes for the prepared stable candidate. Publication is pending owner
review, release-to-main promotion and separate tag/Release authorization. The
only published release remains historical `v0.1.0-beta.1`. No public RC is planned.

## Included

- Independent OpenCode, DeepSeek and GLM through Claude Code agents, with one-,
  two- or three-agent selection and Full or Targeted QA.
- Managed project copies and immutable snapshots shared by the selected agents.
- Grounded findings, source/tool evidence and observable individual agent results.
- Persistent project and run history, cancellation, and JSON/log exports.
- Confirmed project removal, including managed data and history, preserving
  original imported source folders. Active operations prevent removal.
- Windows secure provider settings through Electron safeStorage/DPAPI, with no
  plaintext persistence fallback when secure encryption is unavailable.
- WSL runtime installation, matching Desktop/runtime release identity, graceful
  shutdown, restart and recovery management.
- Optional Windows disk-space reclamation for the selected WSL distro, with
  explicit confirmation and administrator consent. Reclaimable space varies.
- Hardened maintenance privilege boundary: fixed inline execution across UAC,
  private operation-directory ACLs and path validation, and authenticated,
  operation-specific receipts published exclusively and atomically. Existing
  busy-state, cancellation, selected-disk and reconnect safeguards remain.

Historical merger/verifier components remain in the source repository; they are
not advertised as active Desktop workflows.

## Requirements and installation

Supported release target: **Windows 11 x64 + WSL2**, with Ubuntu preferred.
Native Linux Desktop, including CachyOS, is deferred. The Windows application
continues to use its Linux runtime, systemd user services and bubblewrap isolation.

The distribution is an **unsigned ZIP with online WSL runtime bootstrap**.
There is no automatic updater, offline installer, or signed MSI/MSIX/EXE installer.
Windows Node/pnpm/Git are not required for the packaged Desktop. Inside WSL, setup
requires standalone Linux Node >=22, pinned pnpm **9.12.3**, systemd user services,
bubblewrap and socat. Internet is required for setup dependencies and provider
tooling. WSL/prerequisite installation may require manual administrator actions
and a reboot. Third-party provider accounts and usage charges may apply.

Obtain the owner-approved `sentry-1.0.0-<source12>-windows-x64.zip` and matching
SHA256 sidecar through a trusted channel. Verify the checksum, extract to a new
version/source directory, then run:

```powershell
.\sentry.ps1 version
.\sentry.ps1 setup -Distro Ubuntu
.\sentry.ps1 tools -Distro Ubuntu
.\sentry.ps1 open
```

Configure **Settings → Providers**, check **Environment**, then import a project.
See the [installation guide](../setup/distribution.md) for complete checksum,
prerequisite, maintenance and manual upgrade instructions. Never rename an older
archive to claim a new source SHA or extract over an existing installation.

## Compatibility, recovery and limits

This transition changes product identity to `1.0.0`; runtime protocol remains `1`.
Database schemas/migrations, provider/model/tool pins, credential contracts and
project-history formats are unchanged. OpenCode **1.18.32**, DeepSeek SDK
**0.1.5-rc.2** and Claude Code **2.1.270** remain pinned.

Keep stopped paired data/profile backups and matching binaries/runtime. Adopted
[Recovery Option A](v1-recovery-policy-decision.md) retains its tested historical
Windows/I1 source `c78faa74717b0f430a859730e98c3c4915e7b03f` and same-account,
same-machine/DPAPI boundaries. It does not authorize an automatic downgrade,
schema downgrade or cross-account credential restore. The original published
beta executable remains a historically failed credential-rollback target.

Prepared-host packaged acceptance does not establish clean-machine provisioning.
No paid-provider campaign or real elevated compaction of the owner's disk is part
of this release transition. Previous owner-reported agent acceptance retains its
original attribution and source scope. See the [Phase 6.6 handoff](v1-phase-6-6-stable-readiness.md)
for newly executed checks, artifact provenance, delivery and remaining gates.
