# Sentry v1.0.1 — Windows Stable

Windows patch release for **Windows 11 x64 + WSL2**, with Ubuntu preferred.
Download the exact ZIP and checksum using the PowerShell commands on the
[official Release page](https://github.com/Mert1026/Sentry/releases/tag/v1.0.1).
That page is authoritative for publication status, source identity and checksums.

## Fixed

- Python caches/environments, temporary caches and Next/Nuxt build output are
  pruned before new project imports and updates. An unreadable `.pytest_cache`
  no longer prevents importing the source project.
- Unreadable required paths identify the permission error and path. Storage
  exhaustion explains the managed-copy/revision requirement and Windows backing
  disk space under WSL.
- Successful Windows archive setup registers `sentry` on the user PATH. From a
  new PowerShell or Command Prompt window, `sentry open`, `sentry stop`,
  `sentry status`, `sentry doctor` and `sentry version` work from any directory.
- `.\sentry.ps1 register-command` repairs registration after an archive is moved
  without reinstalling the runtime or stopping Desktop.

Source filtering remains separate from frozen v2 hash rules, preserving existing
revision integrity and historical retained bytes. `.gitignore` is not evaluated;
local data directories remain eligible. Explicit include-all imports retain their
full-tree behavior. Source files and permissions are not changed by import.

## Install or upgrade

Use the public Release page's PowerShell download/verification/install block.
It downloads both assets, checks the pinned hash and embedded identity, extracts
into its own version/source directory, installs the matching runtime and pinned
tools, then opens Desktop. Finish or cancel active QA before setup. Keep the
previous matched archive/runtime for recovery; never extract over it.

Setup registers the command for future terminals. In an existing PowerShell:

```powershell
$env:Path += ";$env:LOCALAPPDATA\Sentry\bin"
sentry open
```

Configure Settings → Providers and check Environment before QA. Provider use can
incur charges; installation and diagnostics do not make paid QA requests.

## Compatibility and limits

Product version is `1.0.1`; runtime protocol stays `1`. Database schemas,
migrations, provider/model/tool pins, credential encryption and project-history
formats are unchanged. Existing revision hashes remain valid. Windows provider
settings retain same-account/machine DPAPI boundaries. No automatic downgrade or
schema downgrade is authorized. The historical original beta remains an unaccepted
credential-recovery target; see [recovery policy](v1-recovery-policy-decision.md).

The package is unsigned and uses online runtime bootstrap. Linux Node >=22,
pnpm **9.12.3**, working systemd user services, bubblewrap and socat are required in WSL.
Windows Node/pnpm/Git are not required. Native Linux Desktop remains deferred.
WSL virtual free space alone does not establish Windows backing-drive capacity.
No automatic updater, offline installer or signed MSI/MSIX installer is provided.

Prepared-host verification is not clean-machine acceptance. No paid-provider
campaign or actual elevated disk compaction is part of this patch release.
The v1.0.0 tag and published assets retain their original bytes and identity.
