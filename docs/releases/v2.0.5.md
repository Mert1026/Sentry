# Sentry v2.0.5 — Windows Stable

Windows 11 x64 + WSL2, with Ubuntu preferred. This update from v2.0.4 adds a click-through setup wizard
(`SentrySetup.exe`) that installs everything, including WSL2 and Ubuntu, in English or Bulgarian, with a full
uninstaller; opens the agent's whole live line in a dialog from **Show more**; and adds a Bulgarian user guide.
The ZIP and the setup wizard are unsigned and use online Linux runtime bootstrap. See the
[official Release page](https://github.com/Mert1026/Sentry/releases/tag/v2.0.5) for exact source identity,
asset checksums and PowerShell commands for both fresh installation and updating an existing installation.

## Included

### New: setup wizard (SentrySetup.exe)

- **One click-through installer for a new computer.** It starts with a language choice (English or Bulgarian),
  then installs Sentry per user (no administrator rights to start) and runs six steps with plain status lines:
  checking the computer (Windows 11, virtualization, about 10 GB free), installing WSL2, installing Ubuntu and
  creating the Linux user, preparing the Linux tools, installing the Sentry runtime and installing the agents'
  tools. Windows asks once for administrator approval for WSL.
- **Restarts are handled.** When WSL2 needs a restart, the wizard says so and continues by itself after you sign
  in again. Steps that are already done are skipped when the wizard runs again, so a computer with WSL and Ubuntu
  already set up goes straight to the Sentry steps.
- **Shortcuts with the Sentry logo** in the Start menu and, optionally, on the desktop. **Open Sentry** at the end.
- **Every problem is explained** in the chosen language, with the technical detail and a log at
  `%LOCALAPPDATA%\Sentry\logs\setup-wizard.log`.
- **Full uninstaller** (Settings → Apps). It always removes the program, its shortcuts and the `sentry` command,
  then asks up to three questions, each defaulting to **No**: delete Sentry's data (projects, runs, agent tools and
  saved keys); remove Ubuntu, only if the wizard installed it; remove WSL, only if the wizard installed it and no
  other Linux distribution is left. An Ubuntu or WSL you installed yourself is never offered for removal.
- The wizard wraps exactly the release ZIP. The distribution workflow builds and attests both from the same commit.

### Desktop

- **Show more opens the whole live line in a dialog.** When an agent's current step is longer than its two lines
  on the canvas, **Show more** shows the full step in a dialog, with a **Copy** button. The dialog keeps the step
  you clicked even after the agent moves on, and closes with **Close**, Esc or a click outside it.

### Documentation

- **Bulgarian user guide** (`docs/guide/Sentry-ръководство.pdf`, 30 pages): what Sentry is for, installing (with
  manual WSL and Ubuntu preparation recommended first), the app, starting runs, every round an agent goes through,
  Fast/Full/Re-test compared on a real project, results, settings and troubleshooting, with annotated screenshots.
  It is in the repository, not in the installed app.

## Install with the setup wizard

Download `SentrySetup-2.0.5-<id>-windows-x64.exe` and its `.sha256` file from the Release page, check the checksum
and run it. If Windows SmartScreen shows "Windows protected your PC", choose **More info** → **Run anyway**: the
file is not yet signed with a paid publisher certificate. Preparing WSL and Ubuntu by hand first (see the user
guide, chapter 2) avoids the most common setup problem, creating the Linux user on Ubuntu's first start.

The ZIP install from v2.0.4 and earlier still works unchanged.

## Updating from v2.0.4

There is no database migration in this update. Your projects, runs, history, exports and provider settings are
kept.

1. **Finish or cancel active runs** and wait until they settle.
2. **Download the release ZIP and its `.sha256` file** from the Release page into one folder (for example
   `Downloads\Sentry-v2.0.5`), then run `sentry update` with the ZIP's path:

   ```powershell
   sentry update "C:\Users\you\Downloads\Sentry-v2.0.5\sentry-2.0.5-<id>-windows-x64.zip"
   ```

   It checks the checksum and, when the GitHub CLI (`gh`) is installed, the build attestation. It extracts beside
   the current install, refuses the same or an older version, asks before continuing (`-NonInteractive` skips the
   question), backs up the Desktop profile and the Linux data into `Documents\Sentry backups`, then runs the new
   archive's own setup. If setup fails, the previous install is untouched. It never downloads anything by itself.
   Alternatively run the Release page's **Update an existing installation** block, which works from any earlier
   version. The setup wizard is for new installations; an existing ZIP install is updated with `sentry update`.

3. **Check the result** in a new PowerShell window:

   ```powershell
   sentry version
   sentry status
   ```

   The version must be **2.0.5** and the commit must match the Release page.

Going back to 2.0.4 is safe: no stored format changed. Restore the backup only if you want the data exactly as it
was before the update.

Updating from **2.0.3** or earlier: follow the [v2.0.4 notes](v2.0.4.md) and the notes before it, or run this
update with the Release page's install block. Updating from **1.x**: follow the [v2.0.0 notes](v2.0.0.md); that
update has a one-way database migration.

## Compatibility and verification limits

Product version 2.0.5, runtime protocol 1. There is no database migration and no schema change. Provider and model
pins, credential encryption and revision hash formats are unchanged. Existing v2.0.4 and earlier ZIPs and tags keep
their bytes.

The setup wizard was tested on a second Windows 11 laptop: a full install including the WSL restart and resume, a
QA run in the installed app, and every uninstaller answer. The "Show more" dialog is covered by component tests;
the guide's screenshots come from paid OpenCode runs on a demo project. Native Linux Desktop and macOS are deferred
to a later version. Setup needs internet. The installer and ZIP are unsigned; there is no offline install or
automatic updater. Paid QA runs are separate operator actions. See the Release page for what was verified on the
packaged archive.
